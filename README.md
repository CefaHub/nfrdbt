# Gift Radar

Телеграм-бот, который присылает свежие коллекционные подарки с записью о первоначальном получателе — «кому подарили».

## Уведомление

Пример:

**Spiced Wine #108832**

https://t.me/nft/SpicedWine-108832

Кому подарили: @username  
Модель: ...  
Фон: ...  
Символ: ...

Под сообщением две кнопки: **Открыть подарок** и **Профиль получателя** (если Telegram раскрыл публичный username). Ссылка на NFT показывает превью средствами Telegram.

Первый получатель — не обязательно нынешний владелец. Бот не пытается угадывать личность по отображаемому имени. Если сохранился только Telegram ID, он показывается в тексте, без ненадёжной кнопки.

## Команды

- `/start` — подключение владельца и справка; другие пользователи увидят инструкцию по приглашению.
- `/invite` — владелец получает индивидуальный одноразовый код для друга (действует 24 часа).
- `/join КОД` — друг подключает уведомления на свой аккаунт.
- `/friends` — владелец видит подключённые ID друзей.
- `/remove ID` — владелец отключает одного друга.
- `/leave` — друг самостоятельно отключает подписку.
- `/status` — состояние сканирования и доставки, включая очередь перепроверки.
- `/flush` — немедленно разбудить отправку всех уже найденных, но не доставленных NFT.
- `/pushall` — `/flush` плюс фоновая перепроверка последних 25 номеров каждой известной коллекции (не более 1500 NFT за запуск), а также повторная проверка подарков с задержанной информацией о получателе. Повторный вызов продолжает текущую задачу, а не начинает её заново.
- `/last` — последние подходящие NFT.
- `/pause` и `/resume` — выключить и включить уведомления.

Для технической проверки доставки остаётся скрытая команда `/testdelivery`. Уже использованный код привязки не меняется.

## Как работает

Источники — Telegram MTProto и бесплатный WebSocket see.tg. Из see.tg бот подписывается **только на события new**. Каждое событие перепроверяется через Telegram API. Уведомление отправляется, только если в `StarGiftAttributeOriginalDetails` указан исходный получатель. Листинги, продажи, изменения цен и обычные подарки без получателя не присылаются.

Два источника не создают двойных уведомлений: NFT дедуплицируются по ссылке/номеру. Очередь переживает перезапуск. Если see.tg отключает `new`, остаётся сканирование Telegram; оно может отставать из-за ограничений API.

## Bothost

1. Обнови код из ветки `main`.
2. Проверь переменные окружения по `.env.example`: нужны `BOT_TOKEN`, `SESSION_STRING` и Telegram API ID/hash.
3. Перезапусти бота, затем отправь `/status`.

WebSocket доступен без ключа. `SEE_TG_API_TOKEN` необязателен, хранить его следует только в переменных окружения Bothost. Платные REST-методы see.tg не используются.

`/app/data/state.json` хранит привязку аккаунта, активацию, историю и счётчики NFT. Во время обновления **не удаляй папку data**. Старые записи сохранены для совместимости, но прежние механизмы сделок больше не запускаются.

## Если новые NFT не приходят

Напиши боту **`/pushall`** с привязанного аккаунта, затем смотри **`/status`**:
«Очередь отправки» показывает уже найденные NFT, которые не были отправлены;
«Повторная проверка» — сколько номеров остаётся перепроверить через Telegram.
Отправка и перепроверка ограничиваются по скорости, чтобы не провоцировать FloodWait.

`/flush` не ищет новых NFT, он повторяет доставку накопленной очереди.
`/pushall` перепроверяет ограниченное недавнее окно по ранее известным
коллекциям, **не всю историю Telegram**. Невозможно гарантировать восстановление
NFT, которые не попали ни в один источник, или скрыли историю получателя.
При перезапуске Bothost незаконченная перепроверка продолжится из
`/app/data/state.json`; не удаляй `data`. `/pause` теперь сохраняет
очередь, а `/resume` возобновляет её отправку.

## Уведомления друзьям

NFT ранее отправлялись только одному аккаунту: старый код содержал
`if event.sender_id != state.owner_id: return`, а сообщения всегда
уходили на `owner_id`. Теперь владелец может подключить до 10 друзей.

1. Владелец пишет боту `/invite`.
2. Бот возвращает одноразовую команду `/join СЛУЧАЙНЫЙ_КОД`.
3. Друг отправляет её **этому же** боту из своей личной переписки.
4. С момента подключения новые найденные NFT отправляются и владельцу, и другу.
   Уже доставленные старые NFT автоматически не рассылаются новым участникам.
5. Проверка у друга: `/status` или `/ping`. Управление сканером
   (`/pushall`, `/pause` и проч.) остаётся только у владельца.

Коды приглашений хранятся только как SHA-256, используются один раз и
недействительны через 24 часа. Старый ключ /activate не подключает друзей.
Не публикуй команду с кодом: любой знающий его человек может успеть
подключиться. Сообщения доставляются отдельно каждому получателю;
состояние отправки переживает рестарт, поэтому ошибка у друга не должна
повторно отправлять NFT владельцу. В случае постоянной блокировки бота
подписчиком тот автоматически отключается.
