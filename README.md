# NFT Gift Radar — коммерческая версия для Bothost

Приватный Telegram NFT-радар с автовыдачей **одноразовых ссылок активации**.
Источники — Telegram MTProto и бесплатный поток see.tg. Как и ранее,
радар отбирает подарки с информацией об исходном получателе, но теперь в
сообщении **показывается реальный владелец NFT**, а не человек, которому
подарок был вручён в первый раз. Владелец берётся из Telegram
`starGiftUnique.owner_id` (либо `owner_name` / `owner_address`, когда
Telegram не раскрывает владельца как профиль). Кнопка **«Профиль владельца»**
ведёт на публичный Telegram username, а если username нет, но Telegram
сообщил текущий пользовательский ID владельца — пытается открыть
`tg://user?id=ID`. Такой переход может ограничиваться приватностью
аккаунта. Если указан только TON-адрес или имя без Telegram ID, бот
не выдаёт ссылку на исторического получателя вместо владельца.
Если владелец неизвестен, отобразится «Владелец: Не указан».

## Оплата Telegram Stars через отдельного бота

**Получатель Stars: @nfgtrd22oplbot** — важно: звёзды всегда поступают
**тому Telegram-боту, который выставляет XTR-счёт**, а не произвольному
@username. Нельзя направить Stars другого бота по username без токена.

В этой версии `@nfgtrd22oplbot` может стать отдельным платёжным ботом
на том же Bothost, в одном процессе с радаром и общей SQLite базой.

**Подключение на Bothost:**
1. В @BotFather получи токен **именно @nfgtrd22oplbot** (если раньше
   отправлял токен кому-то или публиковал — сначала перевыпусти).
2. В Bothost добавь скрытые переменные окружения:
   `PAYMENT_BOT_TOKEN=...токен платежного бота...`,
   `STARS_PRICE_1D=...число звёзд...`,
   `STARS_PRICE_LIFETIME=...число звёзд...`.
   Значение `0` отключает продажу соответствующего тарифа. Цены НЕ
   пересчитываются автоматически из рублей; ты задаёшь их сам.
3. Оставь прежние `BOT_TOKEN`, `SESSION_STRING`, `TELEGRAM_API_ID` и
   `TELEGRAM_API_HASH` для радара как были. Платёжный токен должен
   принадлежать **другому** боту, иначе два процесса получения апдейтов
   конфликтуют. Для второй схемы нужна отдельная реализация единого бота.
4. Обнови проект и перезапусти. Не удаляй `/app/data`.
5. Покупатель пишет радару `/buy` и нажимает переход в платёжный бот,
   либо открывает @nfgtrd22oplbot напрямую и использует `/start`.
   Там он выбирает 24 часа или бессрочный тариф, получает официальный
   счёт Telegram Stars (XTR) и оплачивает его.
6. **Только после `successful_payment` от Telegram** запись о платеже
   сохраняется в SQLite и пользователю присваивается выбранный доступ
   по его Telegram ID. Платёжный бот даёт ссылку на радар, где пользователь
   нажимает Start. Никаких произвольных чеков или скриншотов оплаты.

Платёжный бот проверяет username через `getMe` на точное совпадение
с @nfgtrd22oplbot. При ошибочном токене ничего не выставляет. `pre_checkout`
проверяет ID покупателя, цену, XTR и срок действия счёта; повторный
`successful_payment` не выдаёт доступ дважды. Бессрочный доступ
никогда не заменяется дневным. Если в @nfgtrd22oplbot ранее был включён
webhook или запущен другой polling-процесс, его нужно остановить,
иначе обновления оплат сюда не поступят.

Stars идут на баланс @nfgtrd22oplbot. Бот @nfgtrd22oplbot должен
быть под твоим контролем в @BotFather. Поддерживай процедуры возвратов
(`refundStarPayment`) и обращений покупателей.
**Полноценные живые платежи ещё не тестировались** — прежде чем
публиковать новую оплату, проверь небольшой тестовый платёж и получение
доступа с отдельного аккаунта.

### Кнопка «Профиль» в уведомлениях

Текстовая строка **«Владелец: ...»** по-прежнему показывает текущего
владельца, насколько он известен Telegram. Но кнопка **«Профиль»**
по просьбе владельца бота восстановлена из старой версии и открывает
**первоначального получателя подарка**, а не обязательно нынешнего
владельца. Если ссылку на получателя получить нельзя, кнопка не
показывается. Это разные данные.

## Безопасность и доступ

**Единственный администратор — Telegram ID `8714018880`.**

Только этому аккаунту доступны генерация ссылок, /admin, /stats, /status
сканера, /pushall, /flush, /check, /last и /pause /resume. Никакие старые
ключи /activate, приглашения старой версии или прежний owner_id
не дают прав администратора.

Другие пользователи могут только активировать персональную покупку,
получать NFT-уведомления, проверять свою подписку и отключать доставку.
Пользователи **не видят друг друга**, публичного списка подписчиков нет.
Даже администратору бот показывает только общую статистику **без чужих ID**.

**Ограничение анонимности:** для доставки Telegram Bot API/MTProto нужен
chat_id получателя, поэтому он хранится в закрытой SQLite на хостинге.
Telegram и администратор хостинга технически могут иметь доступ к этим
данным. Это приватность между покупателями, а не абсолютная анонимность.

## Две отдельные позиции товара для автовыдачи

**Товар 1 — бессрочный доступ.** Только администратор `8714018880`
создаёт ссылки через `/invite` или `/links 20`. Уже купившие его
пользователи сохраняют бессрочный доступ после обновления базы.

**Товар 2 — доступ на 1 день (24 часа).** Только администратор создаёт
ссылки через `/invite1d` или `/links1d 20`. Каждая ссылка одноразовая,
её можно держать на автовыдаче без таймера. **24 часа начинаются с
фактической активации покупателем**, а не с генерации ссылки или покупки
на Playerok. После 24 часов уведомления автоматически перестают приходить,
команда `/start` не продлевает истёкший доступ. Клиент видит дату
окончания в `/status`. Можно активировать новую дневную ссылку для
продления ещё на 24 часа или бессрочную для окончательного перехода на
постоянную версию — без нового Telegram-аккаунта. Покупка дневного тарифа
пользователем с бессрочным доступом его бессрочный доступ не отменяет.

Ссылки двух товаров **нельзя смешивать в одной корзине автовыдачи**:
`/links 20` — только для бессрочного товара,
`/links1d 20` — только для однодневного.

Срок начинает истекать независимо от частоты обнаружения NFT и
временных ограничений источников. Не обещай, что за сутки обязательно
будут обнаружены новые подарки. Отзывы должны быть добровольными;
доступ продаётся как самостоятельная услуга, а не в обмен на отзыв.

## Продажа через автовыдачу

1. Обнови Bothost до текущего `main` и перезапусти процесс. **Не удаляй
   `/app/data` при обновлении**: там находятся сессия, радар и лицензии.
2. С аккаунта **8714018880** напиши боту `/admin`, затем `/links 20`.
3. Бот выдаст 20 разных ссылок вида:
   `https://t.me/your_bot?start=RANDOM_CODE`.
4. Положи эти ссылки в инвентарь **автовыдачи по одной на покупку**.
5. Покупатель открывает свою ссылку, жмёт Start; доступ активируется
   автоматически, и новые NFT начинают приходить ему в личный чат.
6. Для ещё одной партии — снова `/links 20`, `/links 50` и т.д.
   **Нет общего лимита на число ссылок или подписчиков.** За одну команду
   бот создаёт до 50 ссылок для удобства Telegram-сообщений.
7. Ссылка **одноразовая**, бессрочная; после активации другим человеком не
   сработает. База хранит только SHA-256 хеш кода, не сам секрет.
   Не выкладывай одну и ту же ссылку для нескольких продаж.

Новый покупатель получает только NFT, обнаруженные после подключения.
Старые сообщения и накопленные до продажи находки не рассылаются.

## Команды

### Только администратор 8714018880
- `/admin` или `/start` — панель.
- `/invite` — одна ссылка автовыдачи.
- `/links N` — бессрочные ссылки, партия от 1 до 50, повторять без ограничений.
- `/invite1d` — 1 ссылка с доступом на 24 часа.
- `/links1d N` — от 1 до 50 однодневных ссылок для отдельной автовыдачи.
- `/stats` — агрегированная статистика продаж и подписок, без ID.
- `/status` — здоровье источников и доставки.
- `/pushall` — перепроверить недавние NFT и пробудить доставку.
- `/flush` — только пробудить доставку.
- `/last` — последние NFT.
- `/check SnakeBox-189137` — проверить конкретный подарок.
- `/pause` и `/resume` — остановить/возобновить рассылку.

### Покупатель
- `/start КОД` — автоматическая активация по ссылке, только один раз.
- `/status` — подтвердить подписку и увидеть дату окончания дневного доступа.
- `/stop` — выключить уведомления, не удаляя ранее купленный доступ.
- `/start` — снова включить ранее отключённые уведомления.

Посторонний аккаунт не сможет создать ссылку даже со старым активационным
ключом. Несуществующие административные команды не выводят админ-меню.

## Хранение и масштабирование

`/app/data/commercial.sqlite3` — лицензии с датой истечения (или без неё для бессрочных), SHA-256 кодов, одна общая
запись для каждого NFT и индивидуальный курсор доставки для каждого клиента.
Один найденный NFT хранится **один раз**, не дублируется N раз в JSON.
`/app/data/state.json` — курсоры сканера и последние найденные NFT.

При первом запуске новая версия переносит прежних подписчиков из state.json
в SQLite. Прежний владелец становится обычным получателем, если его ID
отличается от `8714018880`; управлять может только новый администратор.
Не удаляй state.json или commercial.sqlite3 между перезапусками.

*«Безлимитно» означает отсутствие программного лимита пользователей и
общего числа ссылок.* Фактическая скорость доставки ограничена Telegram
(частота отправки, FloodWait), ресурсами тарифа Bothost, диском и нагрузкой.
Например, десятки тысяч подписчиков нельзя гарантированно уведомить за
секунду с одной Telegram-сессии.

## Переменные Bothost

Основные:
- `BOT_TOKEN` (после передачи токена в переписке безопаснее перевыпустить).
- `SESSION_STRING` запасного аккаунта (держи только в секрете Bothost).
- `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` — собственные ключи предпочтительнее.
- `DATA_DIR=/app/data`.

Остальные см. `.env.example`. Главный файл `main.py`. Бот не делает
покупок, не рассылает сообщения владельцам NFT и не обещает обнаружить
каждый выпуск мгновенно.
